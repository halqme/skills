# 評価データの書き方

`evals.json` は、日本語の執筆・推敲依頼を入力したときの振る舞いを確かめるためのケース集。

- `prompt`: モデルに渡す依頼文。
- `expected_output`: **実際に返せる自然な日本語の参考出力例**。望ましい応答そのものを書く。評価者向けの抽象的な説明や「〜を維持する」「〜を避ける」といった採点方針は書かない。
- `assertions`: 出力が満たすべき意味・文体・情報の制約を示す評価観点。参考例との字句一致を求めず、許容できる別表現を評価する。

たとえば情報が不足していて具体的な書き換えができないケースでは、`expected_output` に「不足している情報を説明する、実際の返答例」を書く。内容を勝手に補った具体例は正解にしない。

原文を変えないことが適切なケースでは、原文そのものが `expected_output` になり得る。文章の自然さに唯一の正解があるという意味ではない。
